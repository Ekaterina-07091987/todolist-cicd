# TodoList — клиент-серверное приложение

TodoList — приложение для управления списком задач. Frontend создан на React и Vite, backend — на Node.js и Express. Frontend отправляет запросы через серверную функцию Vercel, которая передаёт их backend-серверу.

## Возможности

- Просмотр списка задач.
- Добавление задачи.
- Редактирование задачи.
- Удаление задачи.
- Проверка API-ключа на backend.
- Отображение количества задач.

## Используемые технологии

- React
- Vite
- Node.js
- Express
- CORS
- dotenv
- Vercel

## Требования

Для локальной разработки установите:

- Node.js;
- npm;
- Vercel CLI — для локального запуска Vercel-функции.

## Локальный запуск

### 1. Запуск backend

Из корневой папки проекта откройте первый терминал и выполните:

```powershell
cd todo-backend
npm install
```

Создайте файл `.env` в папке `todo-backend`. Для локального запуска укажите в нём порт и локальный API-ключ:

```env
PORT=4000
API_KEY=укажите-локальный-ключ
```

Если в проекте есть `.env.example`, его можно скопировать:

```powershell
Copy-Item .env.example .env
```

Проверьте, что в `.env` указаны нужные значения, и запустите backend:

```powershell
node server.js
```

Оставьте этот терминал открытым.

### 2. Настройка frontend-прокси для локального запуска

Frontend использует функцию `todo-frontend/api/tasks.js`. Обычная команда Vite `npm run dev` не запускает эту Vercel-функцию, поэтому для проверки приложения вместе с API используйте Vercel CLI.

Установите Vercel CLI, если он ещё не установлен:

```powershell
npm install -g vercel
```

Создайте файл `todo-frontend/.env.local` со значениями для локальной разработки:

```env
BACKEND_API_URL=http://localhost:4000
API_KEY=тот-же-локальный-ключ-что-в-todo-backend/.env
```

Значение `API_KEY` должно совпадать со значением в `todo-backend/.env`. Файл `.env.local` не добавляйте в Git.

Второй терминал откройте в папке frontend:

```powershell
cd todo-frontend
npm install
vercel dev
```

Если Vercel CLI предложит связать папку с проектом, выберите frontend-проект `todolist-cicd-crbg`. Откройте адрес, который покажет команда `vercel dev`.

## Работа приложения на Vercel

Для просмотра опубликованной версии откройте Production-сайт frontend-проекта в Vercel.

Frontend отправляет запросы на `/api/tasks` на своём домене. Функция `todo-frontend/api/tasks.js` пересылает запросы backend-серверу и добавляет API-ключ на серверной стороне.

## API

| Метод | Маршрут frontend | Действие |
|---|---|---|
| GET | `/api/tasks` | Получить список задач |
| POST | `/api/tasks` | Добавить задачу |
| PUT | `/api/tasks?id=<id>` | Обновить задачу по ID |
| DELETE | `/api/tasks?id=<id>` | Удалить задачу по ID |

Для добавления и обновления задачи передаётся JSON:

```json
{
  "text": "Проверить приложение"
}
```

## Настройки и безопасность

В Vercel используются следующие переменные окружения:

- в backend-проекте — `API_KEY`;
- во frontend-проекте — `BACKEND_API_URL` и `API_KEY`.

Переменные необходимо настроить для Production и Preview. После изменения переменных окружения может потребоваться новый деплой.

Не публикуйте значения API-ключей в README, исходном коде, скриншотах или Git-репозитории. Файлы `.env` и `.env.local` должны оставаться локальными. В `.env.example` указывайте только пример переменных без настоящих секретов.

## Проверка работы

1. Откройте опубликованное приложение или локальную версию, запущенную через `vercel dev`.
2. Добавьте задачу.
3. Проверьте редактирование задачи.
4. Проверьте удаление задачи.
5. Обновите страницу и проверьте загрузку списка.

## Хранение данных

В текущей версии задачи хранятся в памяти backend-сервера. При перезапуске backend список задач может сбрасываться. Для постоянного хранения данных потребуется подключить базу данных.

## CI/CD

Проект связан с GitHub и автоматически развёртывается через Vercel:

- изменения в ветке `main` публикуются в Production;
- изменения в других ветках создают Preview-деплой;
- после слияния pull request в `main` Vercel запускает новый Production-деплой.
